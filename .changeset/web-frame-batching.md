A streaming turn writes the DOM once per animation frame instead of once per delta. Each delta used to write and then measure — a full `marked.parse` of the whole message plus `innerHTML`, then `offsetHeight`, `scrollIntoView` and `scrollTop` — which is a forced synchronous reflow apiece; and `turnEvents` drains its queue through microtasks, so a whole SSE chunk's worth ran in one task with no paint between them. A profile of a real conversation showed hundreds of long frames, most of them from thinking deltas.

Writes are coalesced by a keyed, last-write-wins frame scheduler — the DOM analogue of the machine's `scheduleAtEdge`. The element is created synchronously, so it keeps its place in the stream ahead of any tool block that follows, and only the markdown render and the measurement wait for the frame. The key is the ELEMENT, not the turn: two text blocks either side of a tool call that lands inside one frame share a turn, and keying on the turn let the second block's write evict the first's and leave it permanently empty. The text is captured at schedule time rather than read at fire time, because `tool:end` resets the accumulator and a frame landing after it would blank the message it was meant to complete. Latency is unchanged — a single delta still renders on the very next frame, which a debounce timer could not say.

The one visible change is that a thinking block no longer chases its own bottom past the viewport. It is now bounded by the same fits-the-viewport test the text path has had since continuous bottom-chasing was removed; thinking reached around it by asking only whether any text had arrived yet, which is false for the whole of a long reasoning block. Its guard also reads a flag rather than running a `querySelector` per delta — `textEl` cannot answer "does this wrap have a text block", since finalisation nulls the handle while the node stays.

The height available between the header and the composer is cached instead of measured three times per delta, and invalidated by a `ResizeObserver` on those two boxes rather than at each site that could grow the composer (the textarea autosizing, an attachment strip appearing, the settings panel opening, a font-size change) — that list is one a later feature omits with no error and no symptom, just a fits-the-viewport test quietly answering about the wrong height.
